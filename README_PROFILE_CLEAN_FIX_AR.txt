EgyBook — إصلاحات البروفايل والعلاقات

ما تم تعديله:
1) تثبيت حالة الحساب الذي يتم فتحه وتقليل تداخل بيانات البروفايل السابق.
2) تحميل منشورات الحساب المحدد اعتمادًا على posts.user_id، مع عدّ المنشورات التي يسمح الاستعلام بعرضها فقط.
3) التحقق من علامة التوثيق للحساب المعروض بدل الاعتماد على الحساب المسجل دخوله فقط.
4) إضافة زرّي الصداقة والمتابعة وربطهما باستعلامات Supabase.
5) دعم إرسال/إلغاء الطلب المرسل وقبول الطلب الوارد، وفق حالات friend_requests.
6) معالجة مسار ?route= الذي تنشئه صفحة 404 في GitHub Pages عند استعادة المسارات.
7) إعادة ضبط صورة الغلاف والصورة الشخصية عند الانتقال إلى حساب آخر.

قبل النشر:
- احتفظ بنسخة احتياطية من ملفات الموقع الحالية.
- نفّذ EGYBOOK_PROFILE_RELATIONSHIPS_MIGRATION.sql في Supabase SQL Editor.
- تأكد أن EGYBOOK_FRIEND_REQUESTS_MIGRATION.sql سبق تنفيذه، وأن سياسات RLS موجودة.
- ارفع script.js وstyles.css و404.html والملف SQL الجديد إلى مستودع GitHub.

حدود الاختبار:
- تم فحص صياغة JavaScript باستخدام node --check.
- لم يتم إجراء اتصال حي بقاعدة Supabase من هذه البيئة، لذلك يجب اختبار طلبات الصداقة والمتابعة والتوثيق على حسابين حقيقيين بعد النشر.
- عدد المنشورات المعروض في بروفايل آخر هو عدد المنشورات العامة التي يعيدها الاستعلام، وليس عدد المنشورات الخاصة التي لا يحق للزائر رؤيتها.
- هذه التغييرات لا تنشئ نظام خصوصية كامل للمنشورات الخاصة تلقائيًا؛ يجب ضبط سياسات RLS في جدول posts بما يتوافق مع إعدادات الخصوصية المطلوبة.
