# EgyBook V228 — إصلاح تعارض حركة الهيدين

## سبب الخلل المؤكد من ملفات V227
كان محرك التمرير يكتب الحركة الرأسية في `element.style.transform`، بينما ملف `styles.css` يحتوي على قاعدة موبايل صريحة:

`transform: none !important` على `.bottom-navigation`.

قاعدة CSS ذات `!important` كانت تتغلب على تعيين JavaScript العادي، ولذلك يظل الهيد السفلي ثابتًا بصريًا حتى مع تغيّر قيمة الحركة في JavaScript. هذا يطابق العرض في فيديو EgyBook المرفق.

## ما تغير في V228
- استخدام خاصية CSS المستقلة `translate` للحركة الرأسية في المتصفحات الحديثة؛ وهي لا تستبدل `transform` ولا تتعارض مع قاعدة `transform:none!important` أو توسيط سطح المكتب.
- إبقاء الحركة تدريجية ومتصلة بمقدار التمرير، وليست مجرد تبديل إظهار/إخفاء.
- توفير fallback للمتصفحات القديمة التي لا تدعم `translate`، مع تركيب الحركة على transform الأساسي واستخدام أولوية inline مهمة لتجاوز قاعدة CSS المتعارضة.
- الحفاظ على قصر المحرك على الرئيسية والملف الشخصي وفق هوية الصفحة الحالية.
- تحديث مرجع JavaScript وإصدار Service Worker لتجنب تقديم نسخة V227 من الكاش.

## حدود التحقق
تم فحص فيديو EgyBook وفيديو Facebook، وفحص قواعد CSS وJavaScript في V227، والتحقق من صياغة JavaScript. لم يتم اختبار النشر على أجهزة فعلية أو WebView/Safari؛ يلزم اختبار النسخة بعد رفعها.
