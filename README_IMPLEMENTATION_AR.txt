EgyBook — תיקוני התفاعلات وطلب الصداقة

الملفات المعدلة/المضافة:
- script.js: نافذة التفاعلات تجلب قائمة التفاعلات الفعلية من public.post_reactions وتعرض اسم/صورة/نوع تفاعل كل مستخدم، مع حالة تحميل ورسالة خطأ تشخيصية. زر إضافة صديق يرسل طلبًا إلى friend_requests.
- EGYBOOK_FRIEND_REQUESTS_MIGRATION.sql: إنشاء جدول طلبات الصداقة وسياسات RLS.
- styles.css وindex.html لم يتم تغييرهما في هذه الدفعة لأن التغييرات المطلوبة تمت باستخدام البنية الحالية.

خطوات النشر:
1. احتفظ بنسخة احتياطية من script.js الحالي.
2. استبدل script.js في جذر مستودع GitHub بالنسخة الموجودة في الحزمة.
3. في Supabase SQL Editor نفّذ EGYBOOK_FRIEND_REQUESTS_MIGRATION.sql مرة واحدة.
4. اختبر التفاعلات بحساب قام بالتفاعل فعلًا على منشور موجود، وتأكد من أن جداول post_reactions وprofiles تسمح بالقراءة وأن علاقة FK اللازمة لطلب profiles(full_name, username, avatar_url) صالحة.
5. اختبر إرسال طلب صداقة من حساب إلى حساب آخر.

التحقق:
- اجتاز script.js فحص الصياغة بواسطة node --check.
- لم يتم اختبار الموقع أو Supabase الحي من هذه البيئة.

نطاق وحدود هذه الدفعة:
- تم إصلاح نافذة عرض التفاعلات وإضافة إرسال طلب الصداقة إلى قاعدة البيانات.
- هذه الدفعة لا تنفذ بعد شاشة قبول/رفض طلبات الصداقة، ولا تنشئ قائمة أصدقاء، ولا تربط صفحة منشورات الأصدقاء بعلاقات مقبولة. هذه وظائف إضافية تحتاج واجهة ومنطقًا منفصلين.
- لم يتم تغيير حفظ الملف الشخصي أو ضمان توحيد Realtime بالكامل في هذه الدفعة.
- إذا أظهر الاستعلام خطأ في العلاقة profiles، يلزم مراجعة مخطط profiles/العلاقات في Supabase بدل تعطيل الصلاحيات.
