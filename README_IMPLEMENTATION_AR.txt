EgyBook — إصلاحات البروفايل والعلاقات الاجتماعية
=================================================

محتويات النسخة:
- script.js: تحسين توجيه البروفايلات، منع خلط بيانات الحسابات، تحميل أعداد المنشورات من Supabase، وإضافة أزرار الصداقة والمتابعة.
- styles.css: تنسيق أزرار الصداقة والمتابعة وحماية عرض بعض عناصر البروفايل أثناء تهيئة الحساب.
- EGYBOOK_FRIEND_REQUESTS_MIGRATION.sql: جدول طلبات الصداقة والسياسات، بالإضافة إلى جدول user_follows وسياساته.

خطوات النشر:
1) احتفظ بنسخة احتياطية من ملفات الموقع.
2) ارفع الملفات المحدثة script.js وstyles.css إلى مستودع GitHub.
3) افتح Supabase > SQL Editor ونفّذ EGYBOOK_FRIEND_REQUESTS_MIGRATION.sql مرة واحدة.
   الملف يستخدم CREATE TABLE IF NOT EXISTS، لكنه يحدّث/يعيد إنشاء سياسات محددة؛ راجع سياسات مشروعك قبل التنفيذ.
4) انتظر اكتمال GitHub Pages، ثم افتح الموقع في نافذة خاصة أو امسح الكاش واختبر بحسابين مختلفين.

الاختبارات المنفذة هنا:
- فحص صياغة JavaScript بواسطة node --check: ناجح.
- مراجعة بنية SQL والملفات: تمت.
- لم يتم الاتصال بمشروع Supabase الحي أو تنفيذ SQL نيابةً عنك؛ لم يتم اختبار سياسات RLS على حسابات فعلية.

اختبارات يجب تنفيذها بعد النشر:
1) افتح بروفايل حساب آخر من اسم/صورة صاحب تعليق.
2) تأكد أن الاسم والرابط والصورة وعدد المنشورات تخص الحساب المفتوح.
3) جرّب إرسال طلب صداقة، ثم افتح الحساب المستلم واقبل الطلب.
4) جرّب متابعة المستخدم وإلغاء المتابعة.
5) تأكد أن عدّاد المنشورات يطابق عدد صفوف posts الخاصة بمعرّف صاحب البروفايل.
6) حدّث الصفحة وجرّب الرجوع للأمام والخلف، وتأكد من عدم ظهور حساب آخر أو صفحة غير منسقة.

تنبيهات:
- أزرار الصداقة والمتابعة تعتمد على الجداول والسياسات. إذا ظهرت رسالة خطأ بعد التنفيذ، راجع Console وSupabase Logs.
- هذه النسخة لا تعتبر اختبارًا حيًا ناجحًا. صلاحيات عرض البيانات العامة وقيود الخصوصية ما زالت تعتمد على سياسات الجداول الموجودة في مشروعك.
- التفاعلات والتعليقات تعتمد على جداولها وسياسات RLS الحالية؛ لا يمكن تأكيد حلها نهائيًا من دون اختبار الموقع المنشور.
