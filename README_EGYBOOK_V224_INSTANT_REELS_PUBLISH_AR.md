# EgyBook V224 — ظهور الريل الجديد فور النشر

## المشكلة التي يعالجها الإصدار
كان رفع الفيديو وإنشاء سجل Neon وربطه بمنشور Supabase يكتمل، لكن قائمة Reels الموجودة في ذاكرة الصفحة وكاش أول صفحة لا يتم تحديثهما بعد نجاح النشر. لذلك قد لا يظهر الفيديو الجديد إلا بعد Reload يجلب كتالوج Neon من البداية.

كان هناك مساران مختلفان للنشر:
1. نشر فيديو من مؤلف المنشور العادي عبر `runBackgroundPublish()`.
2. رفع ريل مباشرة من أداة Reels عبر `#reelUploadInput`.

تم توصيل المسارين بنفس تحديث قائمة Reels بعد تأكيد نجاح ربط سجل Neon بمنشور Supabase.

## التعديلات
- حفظ بيانات سجل Neon العائد من إكمال الرفع في خريطة داخل الذاكرة keyed by reel ID.
- إضافة `addPublishedReels()` إلى `EgyBookVideoSourceManager` لإدخال الريل الجديد في بداية قائمة Reels الحالية، أو ترقية العنصر الموجود إذا كان سجل Neon ظهر قبل اكتمال ربط المنشور.
- تحديث كاش أول صفحة للحساب الحالي فقط، مع إزالة صفحات الكاش ذات offsets التي أصبحت قديمة بعد الإدراج.
- منع التكرار بالاعتماد على Reel ID ورابط الفيديو.
- تعديل مؤشر إصدار الكتالوج لمنع استجابة جلب قديمة بدأت قبل النشر من الكتابة فوق الكاش الحديث.
- تعديل مؤشر pagination عند وصول نشر جديد أثناء طلب صفحة قائمة قيد التنفيذ.
- إرسال حدث `egybook:reels-feed-refresh` بعد نجاح النشر لتحديث المستمعات الحالية.

## حماية التشغيل الحالي
- لا يتم فتح الريل الجديد تلقائيًا فوق فيديو يشاهده المستخدم بالفعل.
- عند إدراج عنصر جديد في بداية القائمة، يتم إعادة حساب موضع الفيديو النشط داخل الطابور للحفاظ على نفس الفيديو الحالي.
- لا يتم إيقاف المشغل الحالي أو تغيير `currentTime` أو لمس أحداث السحب والتمرير.
- لم يتم تغيير `video-player.js` أو ملفات CSS للمشغل أو ملفات swipe/infinite-scroll.

## الملفات المطلوبة للنشر
ارفع الملفات المعدلة داخل `egybook_work` فقط. لا يوجد ترحيل SQL جديد ولا تعديل Worker مطلوب في هذا الإصدار.

## الاختبار
تم إجراء فحوص JavaScript syntax، واختبار كاش مستقل للتحقق من إدراج الريل أول القائمة، منع التكرار، إبطال صفحات offsets القديمة، ورفض الروابط التي تحتوي على رموز وصول. كما تم اختبار منطق الطابور محليًا بما في ذلك الإدراج عند وجود عناصر محملة، وتعديل مؤشر pagination، ومعالجة إدراج أثناء وجود طلب تحميل.

لم يتم إجراء نشر حي على GitHub Pages أو اختبار على مشروع Neon/Supabase الفعلي من بيئة البناء. يلزم بعد النشر تجربة المسارين: نشر فيديو من المؤلف العادي ورفع ريل من أداة Reels المباشرة.
