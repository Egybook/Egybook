# EgyBook V246 — Adaptive Device & Runtime Load Guard

التاريخ: 25 نوفمبر 2026  
النسخة الأساسية: `EgyBook_V245_Touch_Scroll_Diagnostics.zip`  
الإصدار: `V246 — Adaptive Device & Runtime Load Guard`

## الهدف

تطوير طبقة الأداء الموجودة بالفعل لتتعامل مع أجهزة مختلفة الإمكانيات، ثم تخفّض بعض الأعمال غير النشطة مؤقتًا عندما يرصد المتصفح ضغطًا متكررًا على خيط JavaScript الرئيسي. الهدف هو تقليل الحمل غير الضروري على مستوى الموقع، مع الحفاظ على تشغيل الوسيط النشط والتنقل والأنظمة المستقرة.

## قرار تصميم مهم: لا توجد قائمة ثابتة بأسماء كل الهواتف

لا ينشئ V246 قاعدة بيانات بموديلات Android وiPhone. بدلًا من ذلك، يقرأ تلميحات قدرات محدودة يتيحها المتصفح مثل `navigator.deviceMemory` و`navigator.hardwareConcurrency`، ويصنف الجهاز إلى أربعة مستويات تقريبية:

- `L1`: اقتصادي/محدود — ذاكرة تقديرية لا تتجاوز 2GB أو 4 أنوية منطقية أو أقل.
- `L2`: متوسط — ذاكرة تقديرية لا تتجاوز 4GB أو 6 أنوية منطقية أو أقل، إذا لم ينطبق L1.
- `L3`: قوي — مؤشرات 8GB و8 أنوية أو أكثر، أو 8 أنوية أو أكثر عندما لا يكشف المتصفح تلميح الذاكرة.
- `L4`: مرتفع جدًا — تلميح ذاكرة 8GB أو أكثر مع 12 نواة منطقية أو أكثر.

هذه حدود تشغيلية تقريبية وليست مواصفات مضمونة أو تحديدًا لموديل الهاتف. القيم التي يعرضها المتصفح قد تكون مقربة أو مخفية. عند غياب المؤشرات يستخدم المحرك `L2` كخط أساس متوازن، ويسجل مستوى الثقة (`two-hints` أو `one-hint` أو `no-hints`).

## كشف ضغط التشغيل

- يراقب المحرك Long Tasks المدعومة في بعض المتصفحات، ولا ينشئ حلقة polling أو RAF دائمة.
- يبدأ وضع الضغط بعد رصد 3 مهام تتجاوز 50ms خلال نافذة 15 ثانية.
- يستمر الوضع 25 ثانية بعد آخر عينة مؤهلة، ثم يعود تلقائيًا عند انتهاء النافذة الهادئة.
- لا تُحتسب المهام أثناء إخفاء الصفحة، وتُصفّر العينات عند مغادرة الصفحة إلى الخلفية أو العودة.
- يصدر المحرك حالة `data-egb-pressure` وحدث `egybook:performance-profile-change` عند تغيّر الحالة.

**هذا ليس حساس حرارة.** واجهات المتصفح المستخدمة لا تقيس درجة حرارة البطارية أو المعالج. `runtime pressure` مؤشر ازدحام/تأخر على خيط الصفحة فقط، ويمكن أن يرتبط بأسباب أخرى غير الحرارة. لا يدّعي V246 معرفة درجة حرارة الجهاز أو السبب الفيزيائي للسخونة.

## كيف يتكيف EgyBook

1. `performance-manager.js`
   - أصبح المحرك المركزي لملف الجهاز والأداء، بدل إنشاء محرك موازٍ.
   - يحافظ على واجهة `EgyBookPerformance.getSnapshot()` وخصائص الوضع الحالية، ويضيف المستوى والثقة وحالة الضغط.
   - يحتفظ بدلالة `data-egb-performance` الحالية للأجهزة المحدودة وتوفير البيانات واحترام تقليل الحركة.

2. `egybook-video-adaptation.js`
   - يقرأ مستوى الجهاز وحالة الضغط من المحرك المركزي.
   - يقلل التهيئة المسبقة لمعاينات Reels المجاورة إلى `metadata` عند الضغط أو القيود.
   - لا يغيّر مصدر المشغل الرئيسي أو جودته أو autoplay أو مالك الصوت أو نظام السحب.

3. `egybook-data-saver.js`
   - يخفض أولوية جلب وسائط الفيديو غير النشطة فقط عند رصد ضغط مستمر.
   - يحتفظ بالفيديو النشط على أولوية التشغيل العالية وسلوك `preload` الحالي.
   - لا يغير إعدادات توفير البيانات التي اختارها المستخدم أو خيارات الجودة المحفوظة.

4. `responsive-optimization.css`
   - أثناء الضغط المؤقت، يوقف تمويه الخلفية عن بطاقات المنشورات والأقسام ومنشئ المنشور، ويوقف العناصر الزخرفية المتحركة عند وجودها.
   - لا يستهدف `.topbar` أو `.bottom-navigation`، ولا يغير موضع الهيدر أو أبعاده أو حركته أو سلوكه.

5. `egybook-performance-diagnostics.js`
   - يضيف `performanceProfile` إلى تقرير JSON، ويشمل مستوى الجهاز وثقة المؤشرات وحالة الضغط وسبب قياس الضغط.
   - يبقى القياس التفصيلي اختياريًا عبر `?egbPerfDebug=1`، وتفاصيل Reels عبر `&videoDebug=1`.

## ما لم يتغير

- مشغل الفيديو الموحد وKeep-Alive وPlayback Coordinator.
- نظام السحب الرأسي الوحيد في Reels وReels Return Recovery وDirect Preview Handoff.
- Persistent Navigation State ومواضع Home/Profile/Reels.
- منطق المشاهدات ونسب الإكمال.
- Unified Notifications Engine.
- Supabase وRLS وSupabase Storage وNeon وCloudflare R2 وWorkers وHovod.
- مسارات الرفع والتخزين والروابط القديمة والبيانات.
- لا تعديل على `script.js` أو الهيدر العلوي أو السفلي.
- لا نشر أو Push إلى GitHub.

## طريقة الاختبار الميداني

بعد نشر V246 يدويًا بالطريقة المعتادة، افتح:

`https://egybook.github.io/Egybook/?egbPerfDebug=1&videoDebug=1`

نفّذ اختبارات منفصلة على Home وProfile وReels، وسجل وقت بدء السخونة ومدى وضوحها، ونوع المتصفح (Chrome أو WebView) ونوع الشبكة. صدّر تقرير الأداء بعد كل صفحة باستخدام زر **تقرير الأداء**.

لا تقارن جلسة الاختبار التشخيصي مباشرة بجلسة عادية على أنها قياس خالص؛ أداة التشخيص نفسها تضيف حملًا محدودًا لأنها تجمع عينات الأداء.

## حدود الإصدار

- لم يُختبر V246 على هاتف فعلي أو على استضافة حية من بيئة التطوير.
- لم يُقَسَ FPS على شاشة فعلية ولم تُقَسَ درجة حرارة البطارية أو المعالج.
- دعم `Long Task API` يختلف بين المتصفحات؛ عند غيابه يظل تصنيف القدرات قائمًا ويظل الضغط غير متاح بدل اختلاق نتيجة.
- مستويات L1–L4 heuristics وليست قائمة معتمدة بكل موديلات الأجهزة؛ يجب مراجعتها بالتقارير الميدانية قبل ضبط عتباتها نهائيًا.
