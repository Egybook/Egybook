# EgyBook V227 — Scroll Header Transform Compatibility

## نطاق الإصلاح
تم إصلاح حركة الهيد العلوي والسفلي على الرئيسية والملف الشخصي فقط.

### السبب التقني الذي عولج
الإصدارات السابقة كانت تعتمد على خاصية CSS الفردية `translate` لتحريك الشريطين رأسيًا. هذه الخاصية أحدث من `transform` وقد لا تُطبّق في بعض إصدارات WebView أو بيئات المتصفح، وهو ما يطابق العَرَض الذي ظهر في الصور: شفافية الهيد تتغير بينما موضعه لا يتحرك بوضوح.

### التعديل في V227
- استخدام `transform: translate3d(...)` لتحريك الهيد العلوي للأعلى والسفلي للأسفل.
- الاحتفاظ بالـ`transform` الأساسي للشريط السفلي حتى لا نفقد التوسيط الأفقي `translateX(-50%)`.
- إعادة قراءة التحويل الأساسي عند تغيير أبعاد الشاشة أو اتجاهها.
- الحفاظ على تقدم الإخفاء الحالي عند `visualViewport.resize` بدل إظهار الشريطين فجأة.
- قراءة موضع التمرير من عنصر التمرير المعتمد أولًا، مع fallback عند الحاجة، لتقليل القفزات الناتجة عن اختلاف قيم viewport.
- تظل الحركة مفعّلة في `home` و`profile` فقط؛ بقية الصفحات تحتفظ بالهيد ظاهرًا.

## الملفات التشغيلية المعدّلة
1. `script.js` — محرك حركة الهيد.
2. `index.html` — تحديث إصدار `script.js` إلى `v=227`.
3. `service-worker.js` — تحديث إصدار الكاش ومرجع `script.js`.

## التوافق والحماية
لم يتم تعديل CSS أو JavaScript الخاص بمشغل الفيديو أو Reels أو السحب الرأسي أو التمرير اللانهائي. لا يوجد SQL جديد ولا يتطلب Worker أو تغييرات في Supabase أو Neon أو R2.

## الاختبارات المحلية
تم فحص صياغة JavaScript وService Worker، واختبار محاكاة منطقية لتحريك الشريطين في اتجاهين متعاكسين، والحفاظ على التوسيط الأفقي للشريط السفلي، والاستجابة لتغيير viewport دون إعادة الإظهار، وقصر الحركة على الرئيسية والملف الشخصي.

لم يتم إجراء اختبار حي على أجهزة Chrome / WebView / Safari الفعلية؛ يجب التحقق بعد النشر على الأجهزة المستخدمة.
