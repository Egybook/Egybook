EgyBook — Account Isolation & Profile Stability V2

التغيير الأساسي:
- فتح ملفات الأصدقاء من بطاقات قائمة الأصدقاء أصبح يمرر Supabase user_id الثابت، وليس اسم المستخدم وحده.
- استعلام الملف العام يستخدم profiles.id مباشرة عند توفر user_id، مع الإبقاء على مسار اسم المستخدم للروابط العامة القديمة.
- تحديد الملف الشخصي الحالي يعتمد على user_id عند توفره، لتقليل الالتباس الناتج عن مقارنة أسماء المستخدمين.
- أضيف user_id إلى أزرار الصور والأسماء وأزرار فتح الملف في بطاقات دليل الأصدقاء.
- استمر استخدام رموز الطلبات الحالية لمنع الاستجابات المتأخرة من تعديل الملف المفتوح بعد الانتقال إلى حساب آخر.

لم يتم:
- تعديل جداول Supabase أو سياسات RLS.
- تنفيذ SQL.
- حذف أو نقل أي بيانات أو وسائط.
- تغيير تصميم الموقع أو نظام الريلز.

الاختبارات المنفذة هنا:
- فحص صياغة JavaScript باستخدام node --check.

اختبارات لازمة بعد النشر:
1. فتح صديق من قائمة أصدقاء الملف الشخصي، والتأكد أن user_id في الملف المعروض يطابق id للصديق.
2. التنقل بسرعة بين صديقين مختلفين، أحدهما لديه منشورات والآخر بلا منشورات.
3. فتح الحساب من بطاقة الصورة والاسم وزر عرض الملف في دليل الأصدقاء.
4. تحديث صفحة صديق مباشرة عبر رابط username والتأكد من استمرار عمل الروابط القديمة.
5. تسجيل الخروج والدخول بحساب آخر والتأكد من عدم ظهور أي بيانات سابقة.

ملاحظة:
هذا الإصلاح يعالج مسار التنقل من قوائم الأصدقاء باستخدام المعرّف الثابت بدل الاعتماد على username وحده. لا يمكن تأكيد حل جميع مظاهر المشكلة قبل اختبار النسخة المنشورة مع حسابين فعليين وفحص سجلات الشبكة عند الحاجة.
