# EgyBook V220 — المرحلة الأولى: ثبات أعداد الريلز ومنع التحميل المتكرر

## ما الذي تعالجه هذه النسخة؟

تعالج هذه المرحلة مشكلة اختفاء/تصفير العدادات مؤقتًا عند فتح أقسام التعليقات والتفاعلات، وتقلل الطلبات المتكررة عند فتح وإغلاق لوحة تعليقات الريلز.

- حفظ لقطة أرقام محدودة لكل منشور داخل `sessionStorage` مع فصلها حسب حساب المستخدم.
- عرض آخر رقم معروف فور ظهور بطاقة المنشور، ثم تحديثه من المصدر الحقيقي دون إظهار صفر مؤقت.
- تخزين بيانات تعليقات الريلز وردودها وتفاعلاتها وملفات أصحابها مؤقتًا لكل حساب ولكل ريل/ترتيب.
- عرض بيانات التعليقات المحفوظة فور فتح اللوحة، ثم إعادة التحقق من Neon في الخلفية عند انتهاء مدة الصلاحية.
- منع تكرار طلب التعليقات أو طلب ملفات الحسابات إذا كان الطلب نفسه ما زال جاريًا.
- عدم مسح التعليقات المعروضة عند فشل التحديث؛ تبقى آخر نسخة معروفة ظاهرة.
- تخزين تفاصيل قائمة تفاعلات المنشور مؤقتًا ومنع إعادة عرض شاشة التحميل في كل فتح.
- حفظ عداد مشاركات الريلز الجديد في Neon عبر جدول `reel_shares` مع معرّف حدث يمنع تكرار نفس العملية عند إعادة المحاولة.

## مصادر الأعداد

- عدد تفاعلات المنشورات/الفيديوهات المرتبطة بمنشور يظل من `Supabase: post_reactions`، دون تغيير مسار حفظ التفاعل الحالي.
- عدد تعليقات الريلز وردودها يأتي من `Neon: reel_comments` عبر Worker.
- عدد مشاركات الريلز الجديدة يأتي من `Neon: reel_shares`.

**ملاحظة تاريخية:** لم يكن مسار مشاركات الريلز في V219 يحفظ سجلات مشاركة دائمة في Neon أو Supabase؛ لذلك لا يمكن استرجاع عدد المشاركات القديمة التي كانت تظهر من حالة الواجهة فقط. يبدأ العد الدائم للمشاركات من نشر V220 وما بعده.

## خطوات النشر

1. افتح Neon SQL Editor في مشروع `egybook-reels`.
2. نفّذ مرة واحدة الملف:
   `SQL/NEON_SQL/EGYBOOK_REELS_STATS_V220_PHASE1.sql`
3. بعد نجاح SQL، انشر ملف Worker التالي إلى `egybook-reels-api`:
   `cloudflare/egybook-reels-api/worker.js`
4. ارفع ملفات الموقع من مجلد `egybook_work` إلى الاستضافة، مع استبدال الملفات القديمة. يتضمن ذلك `index.html` و`script.js` و`reels-comments.js` و`reels-stats.js` و`service-worker.js`.
5. افتح الموقع وأجرِ تحديثًا كاملًا مرة واحدة لتفعيل أصول V220 الجديدة.

لا توجد أوامر SQL جديدة على Supabase في هذه المرحلة، ولا يلزم تغيير أي Secret في Cloudflare.

## ما لم يتغير

- لم تتغير جداول التعليقات أو التفاعلات الموجودة.
- لم يتم نقل البيانات من Neon أو Supabase أو Cloudflare R2.
- لم تتغير قائمة إجراءات تعليقات الريلز المخصصة أو قائمة الصفحة الرئيسية.
- لم تتغير منظومة الإشعارات V217/V218.
- لم تتغير دورة تشغيل الفيديو أو صفحة Reels السوداء/البطيئة؛ تحسين فتح صفحة Reels نفسها هو المرحلة الثانية المنفصلة.

## الاختبارات المنفذة محليًا

- فحص صياغة JavaScript للملفات المعدلة باستخدام `node --check`.
- فحص وجود ملف SQL الجديد وربط `reels-stats.js` في `index.html` وService Worker.
- فحص مسار Neon لحساب المشاركات ومنع تكرار نفس `event_id`.
- فحص المقارنة مع V219 للتأكد من عدم حذف ملفات.

لم يتم إجراء اتصال حي بقاعدة Neon أو Supabase أو Worker المنشور من بيئة البناء؛ لذلك يلزم اختبار فعلي بعد النشر بحسابين.
