# EgyBook V229 — استكمال حالة التنقل وسلاسة الانتقال بين الصفحات

## النسخة الأساسية
تم البناء مباشرة على `EgyBook_V228_Facebook_Scroll_Header_Conflict_Fix.zip` الذي رفعه المستخدم، دون الرجوع إلى إصدار أقدم.

## الهدف
استكمال الجزء الخاص بالتنقل داخل التطبيق من خطة `Persistent Navigation State`، وتقليل الإحساس بأن كل صفحة تبدأ من جديد عند الانتقال بين التبويبات، مع الحفاظ على جلسة Reels ومشغل الفيديو الحاليين.

## ما تم تنفيذه
1. إضافة وحدة مستقلة `egybook-navigation-state.js` لحفظ موضع تمرير كل صفحة أساسية داخل `sessionStorage` الخاص بعلامة التبويب الحالية.
2. حفظ موضع الصفحة المغادرة قبل أن تنفذ الصفحة المستقبلة أوامر العودة إلى أعلى الصفحة.
3. استعادة موضع Home وProfile وبقية الصفحات الأساسية عند العودة إليها من خلال التنقل الداخلي، بعد إطارين للرسم حتى تكون الصفحة قد ظهرت واستقرت.
4. فصل موضع الملف الشخصي حسب اسم المستخدم حتى لا ينتقل موضع ملف شخصي إلى ملف شخصي آخر.
5. إلغاء استعادة قديمة عند حدوث انتقال أسرع منها، مع الحفاظ على لقطة الوجهة المحفوظة بدل استبدالها بموضع مؤقت عند أعلى الصفحة.
6. ترك Back/Forward للمتصفح تحت سيطرة مستعيد موضع سجل التصفح الموجود أصلًا في `script.js`، وعدم إضافة مستعيد منافس له.
7. استثناء Reels من أي استعادة لتمرير النافذة؛ يظل حفظ جلسة الفيديو والوقت والصوت تحت مسؤولية نظام Keep-Alive الحالي.
8. إضافة `data-route-page` إلى سطح Home، وإضافة السمة تلقائيًا إلى صفحة دليل الأصدقاء التي تُنشأ عند الحاجة، للاستفادة من حركة ظهور الصفحات الخفيفة الموجودة أصلًا في CSS.
9. بعد استعادة موضع الصفحة، تصدر الوحدة حدثًا داخليًا محدودًا يعيد مزامنة اتجاه التمرير مع محرك الهيدر الحالي؛ بذلك لا يُفسَّر الانتقال البرمجي كأن المستخدم سحب الصفحة لأسفل، ولا تتغير حالة ظهور الهيدر بسبب الاستعادة.
10. إضافة ملف الوحدة الجديدة إلى قائمة الملفات الأساسية في Service Worker، وتحديث رقم كاشه لمنع تشغيل نسخة قديمة منه، مع مطابقة مرجع `script.js` داخل قائمة الكاش للمسار الفعلي الموجود في HTML.

## نطاق الحماية
تم تعديل `script.js` في مستمع واحد فقط داخل محرك الهيدر لإعادة مزامنة نقطة التمرير بعد الاستعادة. لم يتم تعديل `video-player.js` أو `egybook-reels-experience.js` أو ملفات CSS الخاصة بمشغل الفيديو والسحب الرأسي والتمرير اللانهائي. لم يتم تغيير آلية تشغيل الفيديو أو مصدره أو توقيته أو الصوت أو Hovod أو Neon أو Supabase أو R2 أو Workers أو قواعد البيانات أو سياسات RLS. لم يتم تغيير حركة الهيدر أو مسافاتها أو سلوك إخفائها وإظهارها؛ الإضافة تقتصر على إعادة ضبط نقطة قياس التمرير بعد الاستعادة البرمجية.

## الاختبارات
- فحص الصياغة باستخدام `node --check` لملف التنقل الجديد وService Worker وملف `script.js` الحالي.
- تحليل HTML واستخراج كتل JavaScript المضمنة؛ تم فحص كتل JavaScript التي تحتوي على كود.
- اختبارات محاكاة محلية لحفظ موضع Home وProfile واستعادتهما، واختبار إلغاء الاستعادات القديمة عند التنقل السريع، واستمرار الحالة عبر إعادة تهيئة بيئة التطبيق، وعدم تدخل الوحدة الجديدة في مسار Reels أو Back/Forward.
- لم يتم نشر الإصدار على GitHub Pages، ولم يتم اختباره على هاتف حقيقي أو Chrome/Safari/WebView فعلية، ولم يتم إجراء اختبار حي بحسابات الموقع.

## النشر
انشر محتويات مجلد `egybook_work` إلى مسار الموقع المعتاد مع الحفاظ على بقية الملفات كما هي. لا يوجد SQL أو تعديل Worker أو تغيير إعدادات خدمات خارجية مطلوب لهذا الإصدار.

## ملاحظات وحدود
هذا الإصدار يحفظ مواضع الصفحات الأساسية خلال التنقل الداخلي في نفس علامة تبويب المتصفح. لا يدّعي استعادة عنصر فيديو حي بعد إغلاق الصفحة بالكامل أو قتل المتصفح؛ هذه حالة منفصلة ضمن مرحلة استعادة الخلفية/إعادة التشغيل التالية. كما أن سلاسة الحركة مبنية على انتقالات CSS الموجودة في المشروع، مع توسيعها إلى Home ودليل الأصدقاء، وليست إعادة بناء لنظام التنقل.
