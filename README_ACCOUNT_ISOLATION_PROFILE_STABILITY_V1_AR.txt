EgyBook — Account Isolation & Profile Stability V1

التعديلات:
- ربط قائمة منشورات الملف الشخصي بمعرّف مالك واحد واضح عبر data-profile-owner-id.
- مسح منشورات المالك السابق فور الانتقال إلى حساب مختلف، قبل بدء طلب البيانات الجديد.
- عدم الإبقاء على منشورات الحساب السابق إذا كان الحساب الجديد بلا منشورات.
- منع أي استجابة متأخرة من طلب قديم من تعديل قائمة المنشورات بعد تغير المالك أو رقم الطلب.
- أثناء انتظار تحديد صاحب الملف العام، تظهر حالة انتظار بدل رسالة خطأ مضللة أو محتوى سابق.
- عند تبديل جلسة Supabase إلى حساب آخر أو تسجيل الخروج، يتم إبطال طلبات الملف الشخصي والأصدقاء والعلاقات الجارية ومسح لقطات HTML المؤقتة الخاصة بها.
- تظل بيانات كل حساب مرتبطة بمعرّف Supabase الثابت، ولا يتم استخدام اسم المستخدم كمعرّف ملكية.

الملفات المعدلة:
- script.js

لا توجد تغييرات SQL أو تغييرات في جداول Supabase.
لا يتم نقل أو حذف أي ملفات من Supabase Storage أو R2 ضمن هذا الإصدار.

اختبارات ما قبل النشر:
1. فتح حساب صديق لديه منشورات ثم حساب صديق بلا منشورات؛ يجب ألا تظهر منشورات الحساب الأول في الثاني.
2. التنقل بسرعة بين حسابين؛ يجب تجاهل أي استجابة قديمة تصل متأخرة.
3. فتح قائمة أصدقاء حسابين مختلفين؛ يجب ألا تختلط البطاقات أو الأعداد.
4. تسجيل الخروج والدخول بحساب آخر؛ يجب إبطال اللقطات والطلبات السابقة.
5. اختبار الملف الشخصي بعد تحديث الصفحة مباشرة.
