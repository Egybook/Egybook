EgyBook v185 — ربط بوابة المصادقة المستقلة

الهدف:
- جعل صفحات auth-system هي وجهة تسجيل الدخول/إنشاء الحساب بدل شاشة الترحيب القديمة داخل index.html.
- حل اعتماد الأزرار على مسارات GitHub Pages مكتوبة بحالة أحرف ثابتة؛ أصبحت الروابط تُبنى نسبةً إلى مجلد المشروع الحالي.
- إزالة زر Google من شاشة الترحيب القديمة مؤقتًا حسب قرار المشروع.
- إضافة صفحات Auth وملفاتها إلى قائمة التخزين المسبق في Service Worker مع ترقية إصدار الكاش إلى 185.
- الحفاظ على بقية واجهات وخدمات EgyBook وقاعدة Supabase الحالية.

ما يتغير:
1) index.html: أزرار احتياطية مباشرة لصفحات المصادقة، وإزالة CTA الخاص بـ Google، وتحديث إصدار script.js.
2) script.js: عند عدم وجود جلسة مستخدم، ينتقل الموقع إلى auth-system/login.html مع حفظ رابط العودة. الروابط تحترم مسار GitHub Pages الفعلي.
3) service-worker.js: إصدار 185 وتخزين صفحات المصادقة وملفاتها.
4) auth-system/assets/auth.js: احترام رابط العودة بعد تسجيل الدخول، وفتح تبويب الهاتف تلقائيًا عند طلبه.

الملفات الجديدة:
- README_EGYBOOK_V185_AUTH_GATE_INTEGRATION_AR.txt

الملفات المستبدلة:
- index.html
- script.js
- service-worker.js
- auth-system/assets/auth.js

ما لم يتم تفعيله في هذه المرحلة:
- التحقق عبر Telegram: لا يزال يحتاج Worker/Webhook آمنًا لاستقبال مشاركة رقم الهاتف وإثبات ملكيته. صفحة Telegram الحالية واجهة مبدئية.
- Passkeys: واجهة الاختيار موجودة، لكن التفعيل الحقيقي يحتاج WebAuthn server-side challenge/verification.
- تسجيل الهاتف الحالي عبر Supabase ما زال يعتمد OTP/SMS إلى أن يكتمل مسار Telegram الخلفي. لا تعتبره تحقق Telegram مجانيًا في هذه النسخة.
- يلزم ضبط Redirect URLs في Supabase لنطاق GitHub Pages وصفحات auth-system، واختبار تسجيل الدخول/التسجيل على نسخة تجريبية.

طريقة الرفع إلى GitHub:
- استبدل الملفات الأربعة المذكورة أعلاه في جذر مجلد الموقع، مع رفع README الجديد.
- احتفظ بمجلد auth-system الموجود كما هو ولا تضعه داخل مجلد auth-system آخر.
- بعد النشر افتح الموقع مرة جديدة؛ Service Worker v185 سيحدث الكاش. إذا استمر ظهور نسخة قديمة، أغلق تبويب الموقع وافتحه مجددًا بعد اكتمال التحديث.
