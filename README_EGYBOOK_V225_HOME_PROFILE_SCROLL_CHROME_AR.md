# EgyBook V225 — Home/Profile Finger-Tracked Header Chrome

## نطاق الإصلاح
تم حصر إخفاء/إظهار الشريط العلوي (`.topbar`) والسفلي (`.bottom-navigation`) في صفحتي `home` و`profile` فقط.

## السلوك
- زيادة موضع تمرير المستند تخفي الشريطين تدريجيًا بمقدار يتناسب مباشرة مع فرق التمرير الفعلي.
- عكس اتجاه التمرير يعيد إظهار الشريطين بنفس النسبة؛ لا يوجد تبديل مفاجئ بناءً على عتبة منفصلة.
- عند أعلى الصفحة، أو أثناء الكتابة/وجود نافذة حاجبة، يعود الشريطان للظهور.
- عند تغيير الصفحة، تتم إعادة ضبط موضع الشريطين إلى الظهور، ثم يُسمح بالتتبع فقط إذا كانت الصفحة الجديدة `home` أو `profile`.
- تتم مراقبة تمرير المستند فقط؛ تمرير القوائم الداخلية والتعليقات والريلز لا يحرّك الشريطين.

## عزل الصفحات
تقوم `syncPrimaryNavigationActive()` بنشر معرف الصفحة الحالية في `body.dataset.egybookActivePage` وإطلاق حدث `egybook:primarypagechange`. يعتمد محرك الشريطين على هذا المصدر لتحديد الصفحتين المسموح بهما.

## الحماية
- لم تتغير أحداث اللمس أو `touch-action` أو `scroll` الخاصة بمشغل الفيديو أو نظام السحب الرأسي.
- لم تتغير ملفات CSS الخاصة بالمشغل أو السحب أو التمرير اللانهائي.
- لا توجد تغييرات على Supabase أو Neon أو Cloudflare Worker أو R2 أو SQL.

## الملفات المعدلة
- `script.js`
- `index.html`
- `service-worker.js`

## ملاحظات الاختبار
تم فحص بناء JavaScript وتطابق مراجع الإصدار وقائمة أصول Service Worker. وتم تنفيذ محاكاة منطقية لحالات اتجاه التمرير وتقييد الصفحات. يلزم اختبار فعلي على Chrome وAndroid WebView للتأكد من سلوك اللمس والأداء على الجهاز المستهدف.
