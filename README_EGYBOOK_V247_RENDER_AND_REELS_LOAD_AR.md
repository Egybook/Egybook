# EgyBook V247 — Render Budget & Reels Load Policy

## النسخة الأساسية
- المصدر: `EgyBook_V246_Adaptive_Device_Load_Guard.zip`
- رقم الإصدار الناتج: V247
- الغرض: تحسين توزيع أعمال عرض المنشورات وتوحيد سياسة تحميل معاينات الفيديو المجاورة، مع إضافة قياسات تشخيصية اختيارية لبداية Reels.

## ما تم تغييره

### 1. سياسة تحميل فيديوهات Reels المجاورة
- أصبح `EgyBookVideoAdaptation` هو مصدر القرار المشترك لتحميل الفيديو المجاور.
- تم ربط القرار بثلاثة مسارات كانت تتخذ قرارات متفرقة: ذاكرة الفيديو الدافئة، معاينة السحب، وتجهيز طابور المشغل.
- عند وجود ضغط أداء أو شبكة محدودة، تكون المعاينات المجاورة محافظة (`metadata`) بدل طلب تحميلها بالكامل.
- عند اختيار المستخدم `none` أو `metadata` من إعداد توفير البيانات، تُحترم هذه التفضيلات.
- عند عدم وجود قيود معلومة، تظل أولوية التحميل الكامل للفيديو التالي فقط، بينما يظل السابق `metadata`.
- لم تتغير أولوية الفيديو النشط أو مصدره أو مالك الصوت أو آلية تشغيله.

### 2. Profile — إنشاء البطاقات على دفعات
- تم تحويل إنشاء البطاقات من حلقة متزامنة كبيرة إلى دفعات من 8 بطاقات قبل إتاحة فرصة للمتصفح لمعالجة أعمال أخرى.
- تم استخدام خريطة مفاتيح `Map` لإعادة استخدام البطاقات الموجودة وتجنب استعلام DOM متكرر لكل منشور.
- تم الحفاظ على حد الاستعلام الحالي (500)، والترتيب، والمنشورات المثبتة، وإعادة استخدام العناصر، والكاش، والتحقق من صلاحيات Supabase RLS.
- لا يتم إلغاء تحديث الطلب الأحدث؛ بعد كل إتاحة فرصة للمتصفح تتم مراجعة رمز الطلب وصاحب الملف الشخصي قبل الاستمرار.

### 3. Home وProfile — تهدئة دفعات إحصائيات المنشورات
- أضيفت قائمة انتظار لطلبات الإحصائيات التي يطلقها مراقب ظهور المنشورات.
- الحد الأقصى لعدد المنشورات التي تُحمّل إحصاءاتها في الوقت نفسه هو منشوران.
- لم تتغير استعلامات الإحصائيات نفسها أو حقولها أو معاني الأعداد والتفاعلات.
- الطلبات المباشرة الناتجة عن تفاعل المستخدم أو أحداث المزامنة بقيت على مساراتها الحالية.

### 4. تشخيص بداية Reels
أضيفت قياسات اختيارية لتسجيل:
- هل جاء كتالوج Reels من كاش الحساب أم من Worker، ومدة طلب Worker عند الحاجة.
- مدة استعلام المنشورات المرتبطة التي يراجعها Supabase RLS وعدد المنشورات المسموح بها.
- الزمن حتى يصبح طابور Reels جاهزًا.
- الزمن حتى اختيار أول عنصر، وهل كان مصدر الوسيط مربوطًا وهل وصل عنصر الوسائط إلى حالة جاهزية الإطار الأول.

هذه القياسات لا تتجاوز RLS ولا تسجل روابط الوسائط أو رموز الجلسات أو معرفات المستخدمين. وهي لا تثبت سبب التأخير بمفردها؛ بل تساعد في تحديد المرحلة التي تستغرق الوقت.

لتفعيل تشخيص الفيديو الموجود بالفعل، افتح نسخة الاختبار مع `videoDebug=1`. لا يُنشأ سجل تشخيص الفيديو إلا عند تفعيل أداة التشخيص الاختيارية الموجودة في المشروع.

## ما لم يتم تغييره
- لا تغيير في قواعد البيانات أو الجداول أو الأعمدة أو الفهارس أو سياسات RLS.
- لا تغيير في Supabase أو Supabase Storage أو Neon أو Cloudflare R2 أو Workers.
- لا حذف أو تعطيل لأي مسار تخزين أو رابط وسائط قديم.
- لا تغيير في مشغل الفيديو النشط أو مالك الصوت أو حماية تفعيل الصوت V243.
- لا تغيير في نظام السحب الرأسي الوحيد أو آلية الانتقال أو Reels Return Recovery أو Keep-Alive أو Persistent Navigation State.
- لا تغيير في CSS أو شكل أو موضع أو أبعاد أو حركة أو سلوك الهيدر العلوي أو السفلي.
- لا تغيير في نظام الإشعارات الموحد.
- لم يُنفذ ربط Hovod أو أي نشر أو Git Push.

## ما لم يُدّعَ إصلاحه بعد
- لم يُعلن إصلاح انتظار بداية أول Reel أو الإحساس بقطع بداية الصوت؛ أضيفت قياسات لتحديد هل التأخير في الكتالوج أو RLS أو جاهزية الوسيط أو مرحلة التشغيل/الإطار الأول. لا ينبغي تعديل حراسة الصوت V243 دون دليل.
- لم يُجرَ اختبار فعلي على هاتف المستخدم أو Chrome/WebView/Safari في هذه المرحلة.
- لا توجد قراءة حرارة من تقارير الأداء؛ انخفاض السخونة ملاحظة ميدانية من المستخدم ويجب الحفاظ عليها وقياسها ميدانيًا بعد الاختبار.
