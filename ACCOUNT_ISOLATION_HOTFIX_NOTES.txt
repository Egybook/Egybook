EgyBook — Account Isolation Hotfix

Changed:
- Cloud posts now render the actual author's profile name/avatar fetched from Supabase, rather than the currently logged-in viewer's profile.
- Account switching clears in-memory comments and removes legacy app-specific localStorage keys that could restore stale profile/post state.
- Profile and post caches no longer read/write localStorage; profile and posts use Supabase as the source of truth.
- Local comment cache is disabled; cloud comments are loaded from Supabase.
- A request that finishes after the user switches accounts is ignored to reduce stale-account rendering.

Important limitations:
- This does not prove production behavior until tested on the live GitHub Pages site with two separate Supabase accounts.
- Albums/saved-photo collections are not yet backed by dedicated cloud tables; this hotfix avoids writing those caches locally, so those local-only features need a separate cloud implementation.
- Existing posts are not deleted. Home feed may show posts from multiple users by design; each post should show its real author's name. The profile page should show only posts owned by the signed-in user.
- Do not use the Supabase service-role key in browser code.
